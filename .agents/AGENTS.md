# RTU Level Control — Project Rules

This workspace contains the **RTU Level Control** project: an industrial
data-acquisition system for bitumen tank monitoring based on an
**STM32 NUCLEO-F767ZI**.

The authoritative project baseline is
`Data_Acquisition_Device_Antigravity_Setup.md` in the repository root.
Consult it before making architectural, database, or firmware decisions.

---

## Architecture

- **Controller**: STM32 NUCLEO-F767ZI (Cortex-M7, STM32F767ZIT6).
- **IDE / code generator**: STM32CubeIDE + STM32CubeMX (`.ioc` file).
- **Network stack**: LwIP (bare-metal, no RTOS).
- **Protocols**: Modbus TCP server (port 502), HTTP POST client (port 8080).
- **Local data path**: Nucleo → Modbus TCP → Python collector → PostgreSQL + TimescaleDB.
- **Cloud data path**: Nucleo → HTTP POST (JSON) → FastAPI ingest API → TimescaleDB.

## STM32 Firmware Conventions

- **CubeMX-generated code** lives outside `USER CODE BEGIN` / `USER CODE END`
  blocks and must **never** be hand-edited — it will be overwritten on
  regeneration. All custom code goes inside `USER CODE` blocks.
- Peripheral initialisation functions (e.g. `MX_GPIO_Init`,
  `MX_ADC1_Init`) are generated by CubeMX. Do not modify them directly;
  change the `.ioc` file instead.
- Use HAL drivers (`HAL_*` functions). Do not use direct register access
  unless there is a documented performance reason.
- `printf` is redirected to UART3 via `_write()` in `main.c`.

## Database Conventions

- The local database uses a **normalized schema**: `devices`, `sensors`,
  `readings` (hypertable), `events` (hypertable).
- `readings` stores one row per sensor per poll cycle.
- `events` records state transitions (e.g. relay ON→OFF) with severity.
- Use TimescaleDB hypertables for all time-series data.
- Always include `device_id` in queries and inserts — the schema is
  designed for multi-RTU from day one.

## Important Constraints

These constraints come from the project baseline and must always be
respected:

1.  **Tank geometry varies by client.** Never hard-code one tank
    geometry.
2.  **Multiple RTUs/tanks must be supported.** All schemas and firmware
    must support multi-device from the start.
3.  **Current sampling interval is configurable** (currently 1 s for
    local, defined by `POLL_INTERVAL`).
4.  **One telemetry row represents one sensor on one RTU at one sampling
    instant.**
5.  **Cloud database requires PostgreSQL + TimescaleDB.**
6.  **Cloud Grafana is NOT a requirement.** The final customer interface
    is custom software.
7.  **Communication must be modular.** Do not permanently hard-code
    Ethernet as the only transport.
8.  **Sensor validity must be checked** before calculations or
    comparisons.
9.  **PT ≈ 4 mA (no-pressure) must not be treated as a valid
    pressure-derived level** for disagreement comparison.
10. **Industrial 4–20 mA requires proper signal conditioning.** Never
    connect a 4–20 mA loop directly to a NUCLEO ADC.
11. **PT100 requires proper RTD measurement circuitry.** Do not treat
    a PT100 as a normal voltage output.
12. **Client-specific values must be configurable**, not compiled into
    firmware.
13. **Secrets must never be committed.** Use environment variables or a
    secret manager.
14. **Do not prematurely optimize** for 100+ RTUs; keep the initial
    implementation simple but structurally scalable.
15. When a hardware value, wiring behavior, threshold, sensor protocol,
    or electrical characteristic is **unknown**, explicitly mark it as
    an assumption and verify from actual hardware documentation rather
    than inventing a value.

## Security Rules

- **Never** put passwords, API keys, tokens, private keys, or
  connection strings containing secrets into source code, this
  document, screenshots, or version control.
- Use environment variables (`.env` files excluded from VCS) or a
  dedicated secret manager.
- Known violations to fix: hardcoded `DB_CONNECTION_STRING` in
  `Core/Inc/main.h`, hardcoded `API_KEY` in
  `Core/Src/http_post_client.c`, plaintext `POSTGRES_PASSWORD` in
  `daq_service/docker-compose.yml`.
